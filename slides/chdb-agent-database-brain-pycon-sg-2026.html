A Familiar Agent Failure

Yesterday

The agent tried a migration path, hit a production constraint, and found the correct workaround.

Today

A new task asks for a similar fix. The agent reads the prompt, but not yesterday's decision.

Result

It repeats the failed plan, burns tool calls, and only recovers after more logs and retries.

The problem is not that the model is dumb.
The right context was not queryable at the right time.
Start with the failure. A coding agent forgetting a prior decision is a common experience for Claude Code, Cursor, Codex, or any tool-calling agent.

Context Engineering Needs a Local Database

  • Instructions: rules, constraints, preferences.
  • Working data: files, tables, API results, logs.
  • Memory: decisions, facts, prior solutions.
  • Evaluation history: what worked, what failed, what changed.

Recall means: before each agent step, find the few facts that matter now.

Define recall in plain language. Context is not one prompt blob once it includes instructions, working data, memories, and eval history.

Why Not Just a Vector DB?

Vector Search Is Useful

It finds text that is semantically close to the current task.

But Memory Has Rules

Project scope, privacy, status, tags, conflicts, and pinned decisions matter.

And History Matters

What worked last time? Which memory was edited? Which run failed?

Vector search is just an index.
Agent memory is the whole database around it.
Answer the obvious question early. The argument is not against vector search; it is against using vector search as the entire memory architecture.

ClickHouse in 60 Seconds

Analytical Database

ClickHouse is an open-source database for fast SQL over large tables: logs, events, metrics, traces, and product data.

Columnar Engine

It stores data by column, so scans, filters, joins, and aggregations over millions or billions of rows stay fast.

More Than Storage

It also gives you a serious query engine: SQL, JSON, arrays, text search, and vector distance functions.

Trusted in production by teams building AI, developer tools, infrastructure, and commerce.

Think of it as the engine you use when asking questions over lots of data is the hot path.
Do not assume the room knows ClickHouse. Explain it as an analytical database and query engine before introducing chDB. The logo strip is from the ClickHouse homepage trusted-by section.

One SQL Interface for Files, Tables, and Memory

Local Context

Files, DataFrames, Arrow tables, JSON logs, and persistent local memory tables.

Remote Context

S3, HTTP, Postgres, MySQL, MongoDB, and ClickHouse Cloud via table functions.

Memory Context

Rows with project, tags, privacy, status, embeddings, and event history.

The point is not "more connectors". The point is one query surface for context.

This replaces the database feature-list feeling. Every capability is described as a context source the agent can query.

One Query Can Rank Memory by Meaning, Rules, and Past Use


SELECT
  m.id,
  m.content,
  1 - cosineDistance(m.embedding, {query_vec:Array(Float32)}) AS meaning,
  count(e.id) AS used_before
FROM memories AS m
LEFT JOIN events AS e
  ON e.memory_id = m.id AND e.project_id = m.project_id
WHERE m.project_id = {project:String}
  AND m.status = 'active'
  AND hasAny(m.tags, {tags:Array(String)})
GROUP BY m.id, m.content, m.embedding, m.pinned
ORDER BY m.pinned DESC, meaning DESC, used_before DESC
LIMIT 8;
WHERE
structured project, status, tags
cosine
semantic recall over 256d embeddings
events
task-history signal from prior runs

Slow Memory Calls Waste Tokens

  • Recall sits inside the agent loop.
  • Network jitter becomes thinking-time jitter.
  • Retries resend conversation context.
  • Hot memory is queried many times in one session.

Three Takeaways

  1. Context engineering needs a database. Dynamic context must be filtered, ranked, joined, verified, and evaluated.
  2. Recall should be one SQL. Structured filters, vector similarity, and task-history signals belong in the same query.
  3. Start local, scale cleanly. chDB locally; ClickHouse Server or Cloud when the memory/data layer becomes shared.
