Numbers are read where NumPy keeps them. Strings still need encoding — so "minimal copy", not "zero copy" everywhere.

Three versions to remove every serialization step we could.
[26:30] Engineering slide, one minute. Version 1 was honest but slow: write the DataFrame to Parquet, read it in, write results to Parquet, read them back. Version 2 passed NumPy pointers straight into the engine — 87 times faster input. Version 4 closed the loop on output. Strings are the exception: Python strings have to be encoded, which we rewrote in C++. That's why the abstract says minimal-copy.

[37:30] Newest piece. pg_chdb embeds the chDB library inside a Postgres backend. HONESTY

What not to promise

Not a shared server. One engine per process; for many users, use a server or Cloud.
Remote data is network-bound. A first scan of a big S3 file takes seconds to a minute.
Browser build is young. ~29 MB download, modern browsers only, remote files fetched whole.
pg_chdb is new. Each chdb_query() call is isolated.
Pandas API isn't 100% pandas. Uncovered steps fall back to pandas — correct, not always faster.
Under-promise. The demo does the convincing.
[44:30] Five things to be careful about in front of customers. Each one is real and each has a good answer. If a remote scan is too slow: copy the data into a local MergeTree table once — in my test a 60-second remote aggregation became 19 milliseconds.
