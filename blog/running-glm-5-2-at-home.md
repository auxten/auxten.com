# 在家跑 GLM-5.2：30 token/s 是一道 4.5 万美元的墙

*2026-07-28 — by Auxten Wang*

我想在家跑 GLM-5.2。就是智谱 6 月开源的那个 744B 参数 MoE。

目标很具体：**单流解码 30 token/s**。这大概是 coding agent 用起来不难受的下限。低于这个速度，你会盯着终端里的字一个个往外蹦，忍不住切出去刷 X，然后思路就断了。

互联网对此有无数热情推荐：买 Mac Studio、攒 DGX Spark 集群、上四张 3090。我把能找到的社区实测数据全翻了一遍——r/LocalLLaMA、NVIDIA 开发者论坛、Hugging Face 讨论区、X。

结论先放这：**几乎所有方案都到不了 30 token/s。** 唯一稳定达标的组合要 4.5 万美元。我把结果做成一张表发到 X 上，57K 阅读，然后评论区开始集体反驳我。

这篇文章讲三件事：完整数据、评论区的反驳案例、以及为什么双方可能都没错。

先坦白调研方法，免得显得比实际更严谨：所有数字都来自社区公开实测，不是我自己买了 23 套硬件回来跑分——我没有 5 万美元的业余爱好预算。数据汇总用 Manus 跑的，我人工核对了关键数字和出处。价格是 2026 年 7 月的行情，正值内存危机，波动剧烈。完整调研报告的链接在文末。

---

## 先算物理账

GLM-5.2 是 744B 总参数的 MoE，每个 token 激活约 40B。想跑它，只有两条硬标准。

**第一，装得下。** 各量化级别的内存需求（Unsloth Dynamic GGUF 实测）：

| 量化级别 | 内存占用 | 质量 |
|---|---|---|
| 1-bit（UD-IQ1_S） | ~223 GB | top-1 准确率 ~76%，明显降智 |
| 2-bit（UD-IQ2_M） | ~245 GB | ~82%，可用但有损 |
| 3-bit（UD-Q3_K_XL） | 290–360 GB | 较好 |
| 4-bit（UD-Q4_K_XL） | 372–475 GB | 接近无损 |
| NVFP4（官方） | ~465 GB | 接近无损，仅限 Blackwell |
| FP8（官方） | ~750 GB | 原生精度 |

也就是说，**245 GB 是入场券，370 GB 起步才谈得上"不降智"**。你的 128 GB「AI 小钢炮」，连量化最狠的版本都装不进去。

**第二，读得快。** 解码是带宽游戏：每生成一个 token，都要把约 40B 激活参数的权重完整读一遍，4-bit 下约 20–22 GB。想要 30 tok/s，需要 **600 GB/s 以上的有效带宽**。作为参照：DGX Spark 是 273 GB/s，M3 Ultra 是 819 GB/s，RTX PRO 6000 是 1.79 TB/s。

还有两个变量在搅局。

**MTP 投机解码。** GLM-5.2 内置多 token 预测，每步草拟 5 个 token，能把有效速度拉高 1.5–2.5 倍。但 llama.cpp 至今没实现 GLM 的 MTP，只有 vLLM/SGLang（以及它们的社区补丁版）能用上。同一台机器换个软件栈，速度差一倍，就是这个原因。

**REAP 剪枝版。** 社区用 Cerebras 的 REAP 方法把 256 个专家砍到 168 个，内存需求降 34%。代价是 Terminal-Bench 从 81 分掉到 70.5。省钱，但降智是实打实的。

## 逐条拆开看

### DGX Spark：单台是玩具，八台是方案

单台 Spark 128 GB，装不下任何可用量化，实测 1–4 tok/s。273 GB/s 的内存带宽是它先天的天花板。顺带一提，GB10 芯片有一整个 OEM 克隆家族，ASUS Ascent GX10 只要 $3,499，是同规格最便宜的入口。

真正的玩法是用 ConnectX-7 组集群。4 台跑 AWQ-INT4 加 15% 剪枝加 MTP 是 20–22 tok/s；128K 上下文的 DCP4 配方掉到 14.5–15.2；NF3 混合配方在短上下文能冲到 20–33。

8 台 GB10（~$28k）是这条线的顶配：全量模型加 MTP 稳定 26–27，另一个 INT4/INT8 配方在代码类输出上报告 33–54——**全场唯一有实测数字越过 30 的 3 万美元以内方案**。代价是部署门槛全场最高：100G 交换机、手工打补丁的 vLLM、Triton 内核 hack，社区论坛里全是踩坑记录。

它还有一张隐藏王牌：prefill 有 500–1,200 tok/s。跑 agent 工作流时，这比解码速度更救命。后面讲 Mac 的时候你会明白。

### Mac Studio：曾经的王，输给了 prefill 和内存危机

M3 Ultra 有 819 GB/s 统一内存带宽，曾是大 MoE 的性价比之王。2026 年它挨了两刀。

第一刀：内存危机。Apple 直接下架了 256/512GB 配置，512GB 机器只剩二手，约 $14,200 起，一度被炒到 $25,000。

第二刀：实测不够快。单机 MLX 4-bit 跑全量是 16–18.8 tok/s；两台用 Thunderbolt 5 互联（Ivan Fioravanti 的实测）也只有 23.4。MLX 还没有 GLM 的 MTP 支持，未来若实现可能再提 30–50%，但那是未来。

真正的硬伤是 prefill。llama.cpp 下 33K token 的 prompt 要处理近 10 分钟。你想用它跑 coding agent？动辄 50–100K 上下文，首 token 等 10 分钟起，实际不可用。

### 4× RTX PRO 6000：唯一稳定过线，NVIDIA 也知道

四张卡 384 GB GDDR7，1.79 TB/s 每张。全部权重驻留高带宽显存，vLLM 原生 MTP——这是唯一物理上凑齐所有条件的个人可购组合。

实测：REAP 剪枝版 NVFP4 短上下文约 60 tok/s，64k–100k 上下文仍有 ~45，prefill 5,100；全量不剪枝 IQ4_XS 从 38 起步，40k 上下文降到 29，擦线。

代价明码标价。NVIDIA 今年 6 月把这张卡官方涨价 55% 至 $13,250，早期 $8,500 的街价一去不返。四卡整机 $45,000–55,000，满载 2.2 kW，需要专用电路。**这就是那道墙的价格。**

顺带避坑：两张卡（192 GB）装不下任何全量量化，只能 offload 到内存，13–15 tok/s。$30k 买个高不成低不就。

### 消费级多卡：最热闹，也最令人失望

这是社区尝试最多的路线，结论最残酷。4× 3090 加 192GB DDR5：7.3 tok/s。换成 1-bit 量化，速度居然不变——瓶颈根本不在带宽，在 CPU。

更反直觉的：6× 3090 是 7.8，而 1× 5090 加 Xeon 大内存是 11。**在 offload 路线上，多买显卡几乎无用。** $4,000 到 $10,000 的投入换来 7–12 tok/s，且没有任何升级路径。

### AMD 与 Intel：一个买不到，一个跑不了

双 Strix Halo 互联跑 2-bit：7.2 tok/s，机主自己的结论是「不值得」。Instinct MI300X 系列软件上其实可行，vLLM/SGLang 有官方 ROCm recipe，但只走 B2B 渠道，单卡 $25,000 起，个人基本买不到原厂保修货。

Intel 这边，GLM-5.2 的 GlmMoeDsa 新架构在 IPEX/SYCL 栈上没有任何支持记录，Gaudi 3 个人渠道买不到。最现实的是 Xeon AMX 加 ktransformers（官方有 GLM-5.2 教程），个人配置推算 10–16 tok/s，未达标。

### 服务器 CPU：3,000 美元的门票，进场看个热闹

二手 EPYC 加 512 GB DDR4 约 $2,500–3,500，是「能跑起来」的最低门槛：纯 CPU 1.7–5.5 tok/s，加两张 3090 做 offload 后 6–11。这条路线的意义是花 $3k 体验 744B 模型本身，而不是达到 30 tok/s。

先说明一下蓝 V 意味着什么：X Premium 订阅，8 美元一个月，外加手机号核验。**它核验的是「这是个真人」，不是「这个人的 benchmark 方法论正确」。** 我自己也是蓝 V，这话对我同样成立。

那怎么调和矛盾？我反复对过数据之后的判断是：**他们可能没撒谎，我的表也没算错——我们在测不同的东西。** 有四个变量足以造成这种分歧：

**上下文长度。** NF3 配方在短上下文能冲到 33，128K 上下文的 DCP4 配方只有 14.5。同一套硬件，速度差一倍多。

**MTP 接受率。** 投机解码在代码类输出上接受率高，速度是自由文本的 1.5–2 倍。你跑 coding agent 测出来的数，和我按通用口径记录的数，天然不可比。

**全量还是剪枝。** 这可能是最关键的一条。REAP 剪枝版少读约三分之一的权重，20–22 tok/s 的 4× Spark 换上剪枝版，冲到 30 在物理上完全说得通。0xSero 自己就是剪枝版作者——他说的「GLM-5.2」和我表里的「GLM-5.2 全量」，很可能不是同一个模型。

**单流还是聚合。** 有人报的是多请求并发的总吞吐。这个话题值得单独一节，就是下一节。

至于 40–41：我在公开资料里没找到任何能复现它的 4-Spark 配方，最接近的是 NF3 短上下文的 33。也许存在一个还没公开的更好配方，也许口径不同。没人贴 vLLM 参数和上下文长度，无从验证。**这就是 2026 年本地 LLM benchmark 的现状：没有人在测同一个东西。** 我的表统一取 batch-1、短到中上下文、来源可溯源的口径——你至少知道我在测什么。

## 如果把并发算进来，他们是对的吗？

有一种为 Spark 集群辩护的方式是换口径：两个请求各 20 tok/s，聚合就是 40，达标了。我专门为这个口径做了补充调研，结论比直觉有意思。

对稠密模型来说，并发几乎免费：batch=2 时权重读一遍服务两个请求，吞吐接近翻倍。**但 GLM-5.2 的 MoE 结构把这个红利砍掉了大半。** 每层从 256 个专家里激活 8 个，两个并发请求命中的专家几乎不重叠，路由专家的权重读取量随并发线性增长。能复用的只有注意力和共享专家，约占三分之一。算下来 batch=2 的聚合增益只有 1.2–1.4 倍，不是 2 倍。

实测锚点也支持这个推算：双 GH200 重度 offload 跑 FP8，batch=4 的聚合增益只有 1.16 倍；Apple Silicon 上 MoE 模型 5 路并发是 1.89 倍。而全显存方案完全是另一个世界：8× RTX PRO 6000 从 bs=1 的 106 到 bs=8 的约 420，接近 4 倍。

所以聚合口径下的格局是：

**$28k 档确实翻身了。** 8× GB10 并发 2–4 时聚合 34–46，从擦线变达标；双 M3 Ultra 摸到 29–40；4× Spark 在 bs=4 下勉强够到聚合 30。如果你的真实负载就是多个 agent 并行，每个流 15–25 tok/s 也能接受，$14k–28k 就够了。评论区那些「达标」的声音，一部分可能就是这个口径。

**低价 offload 阵营依然没救。** 瓶颈在系统内存带宽和 CPU，MoE 的专家不重叠让它们的并发增益全场垫底，batch=4 也就从 7 提到 10 出头。地基太慢，并发救不了。

**最反直觉的：4× RTX PRO 6000 反而更划算了。** 单流口径下它是「最贵的达标方案」；聚合口径下它并发 4 预计 150–200，按每单位聚合吞吐算成本约 $300–350 每 tok/s，比 8× GB10 的 $650–700 便宜一半。它可以同时喂 5–8 个 agent，每个还保持 25+ tok/s。

两个工程注意点：并发挤占 KV cache，长上下文和高并发在 128GB/节点的 Spark 上不可兼得（4× Spark 的 128K 配方干脆设了 MAX_NUM_SEQS=1）；MTP 和并发存在竞争，GH200 上开 MTP 后并发 4 的聚合反而从 23.6 掉到 15.2——但同机的 AWQ 配方又是正收益。逐配置实测，别想当然。

## 算总账

按你愿意接受什么，分层推荐：

| 你的要求 | 方案 | 预期速度 | 预算 |
|---|---|---|---|
| 严格单流 ≥30，全量模型质量 | 4× RTX PRO 6000（IQ4_XS） | 29–38 | ~$50k |
| 严格单流 ≥30，接受 REAP 剪枝 | 4× RTX PRO 6000 + NVFP4 | 45–60 | ~$45k–55k |
| ≥30 且主要跑代码，接受折腾 | 8× ASUS GX10 + INT4/INT8 + MTP | 26–27 稳定 / 33–54 峰值 | ~$28k–30k |
| 聚合 ≥30，有真实并发负载 | 8× GB10 或 2× M3 Ultra | 单流 15–25 | ~$28k |
| 接受 ~20，要长上下文 agent | 4× GB10（ASUS 版） | 20–22，prefill 500+ | ~$14k–16k |
| 接受 ~17–23，要安静省电 | 二手 M3 Ultra 512GB ×1 或 ×2 | 16–19 / 23.4 | ~$14k / $28k |
| 只想体验 744B 跑起来 | 二手 EPYC 512GB + 1–2 张 3090 | 6–11 | ~$3k–4.5k |
| 理性经济人 | API 或按小时租卡 | 44+ | $3/M token 或 $2–6/时 |

三点提醒，都是数据里最容易被忽略的。

**第一，30 tok/s 的成本是非线性的。** 20 tok/s 只要 $14k，23 tok/s 要 $28k，「稳定 30+」直接跳到 $45k。最后那 7 个 tok/s 比前面 23 个加起来还贵。想清楚你是不是真的需要 30。

**第二，现在是买 AI 硬件的最差时点。** 内存危机让 Spark 涨了 18%、RTX PRO 6000 涨了 55%、Mac 大内存直接停售。同时 M5 Ultra 传闻 10 月发布，llama.cpp 的 GLM MTP 支持若落地，所有 offload 方案都会提速 50% 以上。如果不急，观望一个季度。

**第三，别只盯着解码，prefill 会杀人。** 30 tok/s 只描述了往外吐字的速度。跑 coding agent 动辄塞 50–100K 上下文：Mac 系 prefill 只有 60–90 tok/s，首 token 要等 10–20 分钟，实际不可用；GB10 集群是 500–1,200；RTX PRO 6000 是 5,000。这个维度上的差距比解码速度更悬殊。

最后是那笔让所有硬件都尴尬的账：GLM-5.2 官方 API 定价 $1.40/M 输入、$4.40/M 输出。**4× RTX PRO 6000 的购机款，够在 API 上买大约 100 亿个输出 token。** 本地部署的理由只剩四个：隐私、离线、无限调用、研究癖。我承认我主要是最后一种。
